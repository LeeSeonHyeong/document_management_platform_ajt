# Wiki 파일 반영 보상 처리 설계

## 목적

Wiki 변환 반영에서 파일 시스템은 DB 트랜잭션에 참여하지 않는다. 따라서 Wiki 본문 또는 `index.md`를 바꾼 뒤 DB 반영이 실패하면, 파일도 반영 전 상태로 되돌려 DB·파일 불일치를 막는다.

## 범위

- Wiki 본문 생성·수정·삭제와 공간별 `index.md` 기록
- 반영 중 예외와 Spring DB 트랜잭션 롤백에 대한 파일 복원
- 동일 파일 시스템 안에서 임시 파일을 원자적으로 대상 경로에 교체

프로세스 강제 종료 뒤 복구, 보존 기간을 둔 작업공간, 원본 문서 및 일정 파일은 범위 밖이다.

## 구성

`WikiFileStorage.beginMutation()`은 반영 단위의 `WikiFileMutation`을 반환한다.

1. 각 대상 경로는 첫 변경 직전에 원래 바이트(없음 포함)를 기록한다.
2. 쓰기는 대상 경로와 같은 디렉터리의 임시 파일을 만든 뒤 `ATOMIC_MOVE`로 교체한다.
3. 삭제도 원래 바이트를 기록한 뒤 실행한다.
4. `WikiTransformationApplier`는 파일 반영 중 예외가 나면 즉시 `rollback()`을 실행한다.
5. 정상 반환 뒤에는 Spring `TransactionSynchronization.afterCompletion`에서 DB 결과를 확인한다.
   - 커밋: 기록한 원본 상태를 폐기한다.
   - 롤백: 기록한 원본 상태를 역순으로 복원한다. 원래 없던 파일은 삭제한다.

## 제약과 후속 작업

원자적 이동을 지원하지 않는 파일 시스템은 반영을 실패 처리한다. 예외 상황에서 비원자적 복사를 허용하면 DR-008의 파일 교체 보장을 약화시키기 때문이다.

현재 보상 정보는 프로세스 메모리에 있으므로 JVM 강제 종료 중간에는 자동 복구할 수 없다. DR-007~010의 작업공간·백업 보존·재시작 복구는 별도 작업으로 확장한다.
