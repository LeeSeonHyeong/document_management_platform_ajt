# 03. DB 덤프 가이드

DB 스키마 구성과 덤프 파일 생성·복원 절차를 기술한다.

---

## 1. 데이터베이스 개요

| 항목 | 값 |
| --- | --- |
| 제품 | MySQL 8.4 (`mysql:8.4` 공식 이미지) |
| DB명 | `ajt` |
| 문자셋 / 콜레이션 | `utf8mb4` / `utf8mb4_0900_ai_ci` |
| 스토리지 엔진 | InnoDB |
| 타임존 | **UTC 저장** (`hibernate.jdbc.time_zone: UTC`) |
| 스키마 SSOT | `docs/db/erd.sql` |
| 접속 계정 | `ajt` (앱) / `root` (운영·덤프) |
| 데이터 볼륨 | `ajt-prod-mysql-data` |

> ⚠️ **DB 스키마 변경 금지 원칙**
> `docs/db/erd.sql`이 정본이다. 코드와 어긋나면 ERD를 정답으로 보고 엔티티를 맞춘다.
> ERD 자체를 바꿔야 하면 팀 합의 후 진행한다.

## 3. 덤프 파일 위치

```
exec/
└── db/
    └── ajt_dump_YYYYMMDD.sql      ← 최신 덤프 파일
```

> 덤프 파일은 데이터 시점이 있으므로 **제출 직전에 최신본으로 재생성**한다.
> 파일명에 생성 일자를 반드시 포함한다.

---

## 4. 덤프 생성 절차

### 4.1 운영 서버 (Docker Compose 환경)

```bash
# 1) 서버 접속 후 저장소 디렉터리로 이동
cd /path/to/S15P11B106

# 2) 전체 덤프 (스키마 + 데이터)
docker compose --project-name ajt-prod exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump \
    -uroot \
    --default-character-set=utf8mb4 \
    --single-transaction \
    --routines --triggers --events \
    --set-gtid-purged=OFF \
    ajt' \
  > exec/db/ajt_dump_$(date +%Y%m%d).sql
```

| 옵션 | 이유 |
| --- | --- |
| `--single-transaction` | InnoDB를 잠그지 않고 일관된 스냅샷 확보 (서비스 무중단) |
| `--default-character-set=utf8mb4` | 한글 깨짐 방지 |
| `--routines --triggers --events` | 프로시저·트리거·이벤트 포함 |
| `--set-gtid-purged=OFF` | 복원 시 GTID 충돌 방지 |
| `-T` (compose exec) | TTY 미할당 — 리다이렉트 출력에 제어문자가 섞이지 않게 |

### 4.2 스키마만 덤프

```bash
docker compose --project-name ajt-prod exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump \
    -uroot --default-character-set=utf8mb4 --no-data ajt' \
  > exec/db/ajt_schema_$(date +%Y%m%d).sql
```

### 4.3 데이터만 덤프

```bash
docker compose --project-name ajt-prod exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump \
    -uroot --default-character-set=utf8mb4 --no-create-info ajt' \
  > exec/db/ajt_data_$(date +%Y%m%d).sql
```

### 4.4 생성 후 확인

```bash
ls -lh exec/db/
head -30 exec/db/ajt_dump_*.sql          # 헤더에 서버 버전·DB명 확인
grep -c 'CREATE TABLE' exec/db/ajt_dump_*.sql   # 17 이 나와야 정상
```

## 5. 복원 절차

### 5.1 신규 환경 — 스키마만 (권장)

빈 볼륨으로 최초 기동하면 `docker-compose.yml`이 `docs/db/erd.sql`을
`/docker-entrypoint-initdb.d/01-schema.sql`로 마운트해 **자동 실행**한다.
따라서 별도 복원 없이 스키마가 만들어진다.

```bash
docker compose --project-name ajt-prod --env-file .env up -d
bash scripts/bootstrap-admin.sh     # 최고관리자 생성
```

> 초기화 스크립트는 **데이터 볼륨이 비어 있을 때만 1회** 실행된다.

### 5.2 덤프 파일로 복원

```bash
# 컨테이너가 떠 있는 상태에서
docker compose --project-name ajt-prod exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql \
    -uroot --default-character-set=utf8mb4 ajt' \
  < exec/db/ajt_dump_YYYYMMDD.sql
```

### 5.3 완전 초기화 후 복원 (데이터 전손 주의)

```bash
docker compose --project-name ajt-prod down
docker volume rm ajt-prod-mysql-data          # ⚠️ 기존 데이터 삭제
docker compose --project-name ajt-prod --env-file .env up -d
# mysql 이 healthy 가 될 때까지 대기 후
docker compose --project-name ajt-prod exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot ajt' \
  < exec/db/ajt_dump_YYYYMMDD.sql
```

## 6. 업로드 파일 백업 (DB와 별도)

원본문서·첨부파일은 DB가 아니라 **볼륨(`ajt-prod-files`)에 저장**된다.
DB만 복원하면 문서 메타는 있는데 실제 파일이 없는 상태가 되므로 함께 백업해야 한다.

| 경로 | 내용 |
| --- | --- |
| `/data/ajt/documents` | 원본문서 |
| `/data/ajt/schedule-sources` | 일정 원본문서 |
| `/data/ajt/inquiries` | 문의 첨부 |

```bash
# 백업
docker run --rm \
  -v ajt-prod-files:/data:ro \
  -v "$PWD/exec/db":/backup \
  alpine tar czf /backup/ajt_files_$(date +%Y%m%d).tar.gz -C /data .

# 복원
docker run --rm \
  -v ajt-prod-files:/data \
  -v "$PWD/exec/db":/backup \
  alpine sh -c 'tar xzf /backup/ajt_files_YYYYMMDD.tar.gz -C /data'
```

## 7. 시연용 더미 데이터 (덤프 불필요)

콘텐츠가 채워진 화면을 빠르게 띄우려면 **`local` 프로파일 데모 스택**을 쓴다.
H2 인메모리 + `LocalDataInitializer`가 더미데이터를 자동 시드하므로 DB 덤프가 필요 없다.

```bash
docker compose -f docker-compose.demo.yml -p demo --env-file .env.demo up -d --build
```

| 항목 | 값 |
| --- | --- |
| 접속 포트 | `FRONTEND_PORT` (기본 **8090**, HTTPS) |
| DB | H2 인메모리 (MySQL 불필요) |
| 로그인 | `admin@ajt.com` / `password123!` |
| 그 외 계정 | 모두 비밀번호 `password123!` |

> ⚠️ 컨테이너 재시작 시 **데이터가 초기화**된다. 라이브 시연에는 무방하나 운영에는 쓰지 않는다.

## 8. 체크리스트

- [ ] 덤프 파일이 `exec/db/` 아래에 있는가
- [ ] 파일명에 생성 일자가 있는가 (`ajt_dump_YYYYMMDD.sql`)
- [ ] `CREATE TABLE` 개수가 **17개**인가
- [ ] 한글이 깨지지 않는가 (`utf8mb4`)
- [ ] 덤프에 **비밀번호 해시 외 평문 비밀정보가 없는가**
- [ ] 업로드 파일 볼륨 백업이 필요한 시연인지 확인했는가
