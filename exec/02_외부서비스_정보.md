# 02. 외부 서비스 정보

프로젝트가 사용하는 외부 서비스의 가입·발급·설정 방법을 정리한다.

> 🔴 **실제 키 값은 본 문서에 기재하지 않는다.** 서버의 시크릿 파일(`prod.env`)에만 보관한다.

---

## 요약

| # | 서비스 | 용도 | 필수 여부 | 환경변수 |
| --- | --- | --- | --- | --- |
| 1 | **Anthropic API** (SSAFY GMS 경유 가능) | 위키 변환 에이전트, 챗봇 답변, 일정 추출 | **필수** | `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL` |
| 2 | **Google AI Studio** (Gemini) | 스캔 PDF 비전 OCR | 권장 | `GEMINI_API_KEY` |
| 3 | **Naver SMTP** | 비밀번호 재설정 인증번호 메일 | 필수(해당 기능) | `MAIL_USERNAME`, `MAIL_PASSWORD` |
| 4 | **Let's Encrypt** | HTTPS TLS 인증서 | **필수** | (파일 마운트) |
| 5 | **LangSmith** | 에이전트 실행 트레이스 관측 | 선택 | `LANGSMITH_*` |

> 소셜 로그인(OAuth), 결제, 포톤 클라우드, 코드 컴파일 서비스는 **사용하지 않는다.**
> 인증은 자체 JWT 기반이며, 회원가입은 관리자 승인 방식이다.

## 1. Anthropic API — 필수 (SSAFY GMS 게이트웨이 경유 가능)

모든 LLM 호출은 Anthropic Messages API 로 나간다. **경유 여부는 `ANTHROPIC_BASE_URL` 하나로
정해진다.**

| `ANTHROPIC_BASE_URL` | 호출 대상 | 키 | 과금 |
| --- | --- | --- | --- |
| 비움 | `api.anthropic.com` (직접) | Anthropic 발급 키(`sk-ant-…`) | 해당 계정 |
| GMS 주소 지정 | `gms.ssafy.io` 경유 | SSAFY GMS 발급 키 | SSAFY 크레딧 |

> 🟡 **현재 배포 서버(prod·develop)는 `ANTHROPIC_BASE_URL` 을 비운 채 Anthropic API 를 직접
> 호출한다.** 포팅 시 GMS 크레딧을 쓰려면 아래대로 값과 키를 **함께** 바꾼다 — 주소만 GMS 로
> 바꾸고 키가 Anthropic 발급 키이면 게이트웨이에서 인증에 실패한다.
>
> 키와 주소가 어긋나 401 이 난 사례가 있다. 다른 프로젝트(`S15P12B…`)의 GMS 키가 들어가 있었고,
> 발급처가 다르면 형식이 맞아도 통하지 않는다. **키는 이 프로젝트로 발급받은 것이어야 한다.**

### 개요

| 항목 | 값 |
| --- | --- |
| Base URL | `https://gms.ssafy.io/gmsapi/api.anthropic.com` |
| URL 패턴 | `https://gms.ssafy.io/gmsapi/<업스트림 호스트>` |
| 인증 | `ANTHROPIC_API_KEY` |
| 배포 설정 | `ANTHROPIC_BASE_URL=https://gms.ssafy.io/gmsapi/api.anthropic.com` |
| 과금 | SSAFY 제공 크레딧 |

### 가입 및 키 발급

1. SSAFY GMS 포털에 교육생 계정으로 로그인
2. API Key 발급 메뉴에서 키 생성
3. 발급된 키를 서버 시크릿 파일에 저장

```bash
# /var/lib/jenkins/ajt-secrets/prod.env
ANTHROPIC_API_KEY=<발급받은 키>
ANTHROPIC_BASE_URL=https://gms.ssafy.io/gmsapi/api.anthropic.com
```

### 사용 모델

GMS에서 사용 가능이 확인된 Anthropic 모델 (2026-07-29 기준).

> 🟡 **아래 가용·불가 목록과 100KB 제한은 개발 중 확인한 값이나 저장소에 측정 기록이 남아 있지
> 않다.** 제출 전 담당자가 재확인하거나 근거 위치를 명시한다. GMS 정책은 시점에 따라 바뀐다.

| 용도 | 모델 | 환경변수 |
| --- | --- | --- |
| 위키 편집 에이전트 (기본) | `claude-sonnet-4-6` | `AI_MODEL`, `AI_MODEL_QUALITY` |
| 경량 단발 호출 / OCR 폴백 | `claude-haiku-4-5-20251001` | `AI_MODEL_FAST` |
| 일정 추출 | `claude-haiku-4-5-20251001` | `SCHEDULE_EXTRACTOR_MODEL` |

그 외 사용 가능: `claude-sonnet-4-5-20250929`, `claude-opus-4-6`
**사용 불가**: `claude-sonnet-5`, `claude-sonnet-4-5`, `claude-haiku-4-5`, `claude-opus-4-5`

> ⚠️ 모델명은 **정확한 전체 이름**을 쓴다. `opus` 같은 별칭은 시점에 따라 다른 모델로 해석되어
> 측정 비교를 조용히 깨뜨린다.

### 제약사항 ⚠️

- **요청 본문 크기 약 100KB 제한**(개발 중 확인, 측정 기록 없음 — 위 주의 참고).
  200dpi로 렌더한 스캔 PDF 페이지 대부분이 여기 걸린다.
  - 이때 `model not found` 오류로 잘못 보고되는데, 실제 원인은 게이트웨이의 크기 제한이다.
  - 이 때문에 스캔 PDF OCR은 Gemini(2번)를 별도로 사용한다.
- 배포 서버에 GPU가 없어 Ollama 대안을 쓸 수 없다. GMS 장애 시 AI 기능 전체가 중단된다.

## 2. Google AI Studio (Gemini) — 스캔 PDF OCR

### 개요

| 항목 | 값 |
| --- | --- |
| 서비스 | Google AI Studio (Generative Language API) |
| Base URL | `https://generativelanguage.googleapis.com` (기본값) |
| 사용 모델 | `gemini-flash-lite-latest` |
| 요금제 | 무료 티어 |
| 환경변수 | `GEMINI_API_KEY`, `GEMINI_MODEL`, `VISION_OCR_PROVIDER=gemini` |

### 가입 및 키 발급

1. https://aistudio.google.com 접속 후 Google 계정으로 로그인
2. **Get API key** → **Create API key** 로 키 생성
3. 서버 시크릿 파일에 저장

```bash
GEMINI_API_KEY=<발급받은 키>
```

### 사용 이유

GMS 게이트웨이의 ~100KB 본문 제한 때문에 Anthropic 경로로는 실제 스캔 페이지 OCR이 거의 실패한다.
Google API는 GMS를 거치지 않아 이 제약이 없다.

### 제약사항 ⚠️

- **모델명 주의**: `gemini-2.0-flash` 계열은 무료 티어 할당량이 0으로 배정된 사례가 있었다(2026-08-03 확인,
  측정 기록은 남아 있지 않다 — 재확인 필요). 요청이 실제로 통과하는 `gemini-flash-lite-latest`를 사용한다.
- **키가 없어도 기동은 된다.** 다만 로컬 Tesseract로 폴백하며,
  컨테이너에 **한글 언어팩이 없어 한글 스캔 문서는 실패**한다.
- 무료 티어의 분당·일일 요청 제한이 있다. 시연 직전 대량 업로드 시 주의.

## 3. Naver SMTP — 비밀번호 재설정 메일

### 개요

| 항목 | 값 |
| --- | --- |
| 호스트 | `smtp.naver.com` |
| 포트 | `465` (SSL) |
| 인증 | `mail.smtp.auth: true`, `mail.smtp.ssl.enable: true` |
| 용도 | 비밀번호 재설정 6자리 인증번호 발송 |
| 환경변수 | `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` |

### 설정 방법

1. 네이버 메일 로그인 → **환경설정 → POP3/IMAP 설정** → **IMAP/SMTP 사용함**으로 변경
2. 네이버 계정에 2단계 인증이 걸려 있으면 **애플리케이션 비밀번호**를 별도 발급
3. 서버 시크릿 파일에 저장

```bash
MAIL_HOST=smtp.naver.com
MAIL_PORT=465
MAIL_USERNAME=<네이버 아이디>          # @naver.com 제외
MAIL_PASSWORD=<비밀번호 또는 앱 비밀번호>
MAIL_FROM=<발신 표기 주소>
```

### 제약사항 ⚠️

- 네이버는 **일일 발송 한도**가 있다. 시연 중 반복 요청 시 차단될 수 있다.
- 미설정 시(`MAIL_USERNAME` 빈 값) 비밀번호 재설정 기능만 동작하지 않고 나머지 서비스는 정상이다.
  - 다만 Actuator `/actuator/health` 가 `DOWN` 으로 보인다(`MailHealthIndicator` 가 SMTP 연결을
    확인한다). **배포 실패가 아니다** — 배포 헬스체크는 `/api/v1/health` 를 본다.
- 다른 SMTP(Gmail 등)로 교체하려면 `MAIL_HOST`/`MAIL_PORT`만 바꾸면 된다.

## 4. Let's Encrypt — TLS 인증서 (필수)

### 개요

| 항목 | 값 |
| --- | --- |
| 도메인 | `i15b106.p.ssafy.io` |
| 인증서 경로 | `/etc/letsencrypt/live/i15b106.p.ssafy.io/` |
| 사용 파일 | `fullchain.pem`, `privkey.pem` |
| 컨테이너 마운트 | `/etc/letsencrypt:/etc/letsencrypt:ro` |

### 발급 방법

```bash
sudo apt-get install -y certbot

# 443 을 쓰는 컨테이너를 잠시 내린 뒤 발급
docker compose --project-name ajt-prod stop frontend
sudo certbot certonly --standalone -d i15b106.p.ssafy.io
docker compose --project-name ajt-prod start frontend
```

### 갱신

```bash
sudo certbot renew
docker compose --project-name ajt-prod restart frontend   # nginx 가 새 인증서를 다시 읽도록
```

### 제약사항 ⚠️

- 인증서 유효기간 **90일**. 갱신 후 frontend 컨테이너 재시작이 필요하다.
- 인증서 파일이 없으면 **nginx가 기동에 실패**한다.
- 도메인을 바꾸면 `frontend/nginx.conf`의 경로 2줄을 수정하고 **이미지를 재빌드**해야 한다.

## 5. LangSmith — 에이전트 관측 (선택)

에이전트 실행 트레이스를 기록해 위키 변환 과정을 분석할 때만 사용한다. **운영에 필수가 아니다.**

| 환경변수 | 설명 |
| --- | --- |
| `LANGSMITH_TRACING` | `true`로 설정 시 활성화 |
| `LANGSMITH_API_KEY` | https://smith.langchain.com 에서 발급 |
| `LANGSMITH_PROJECT` | 프로젝트 이름 |

> **셋 다 있어야 켜진다.** 하나라도 비면 아무 동작도 하지 않는다.
> `docker-compose.yml`은 세 값을 AI 컨테이너로 전달하며, `LANGSMITH_TRACING=true`일 때만
> 외부로 트레이스를 전송한다.

## 6. 사용하지 않는 외부 서비스

포팅 시 준비할 필요가 없는 항목이다.

| 항목 | 사용 여부 | 대체 방식 |
| --- | --- | --- |
| 소셜 로그인 (OAuth/OIDC) | ❌ | 자체 JWT + 관리자 승인 회원가입 |
| 결제 서비스 | ❌ | — |
| 포톤 클라우드 / 실시간 통신 | ❌ | — |
| 외부 코드 컴파일 서비스 | ❌ | — |
| 클라우드 스토리지 (S3 등) | ❌ | Docker 볼륨 로컬 저장 (`/data/ajt`) |
| 외부 벡터 DB | ❌ | MySQL `wiki_search_chunk` 테이블 기반 자체 검색 |
| Ollama (로컬 LLM) | ❌ | 서버에 GPU가 없어 GMS로 고정 |

## 7. 시크릿 관리 원칙

- 실제 키는 **서버의 `/var/lib/jenkins/ajt-secrets/*.env`에만** 둔다.
- 저장소에는 값이 빈 템플릿(`.env.example`, `ai/src/.env.example`)만 커밋한다.
- 키 유출 시 조치:
  - `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` → 각 콘솔에서 폐기 후 재발급
  - `AJT_ACCESS_TOKEN_SECRET` → 재발급 시 **기존 로그인 세션이 모두 무효화**된다
  - `AI_INTERNAL_API_KEY` → backend·ai 양쪽을 **동시에** 갱신해야 한다 (한쪽만 바꾸면 전부 401)
