# 문의 담당자·일정 파일 정합성 설계

## 목적

관리자·사원 PNG 와이어프레임은 별도로 수정된 것으로 보고, 요구사항 정의서와 Postman 명세를 다음 확정 정책으로 통일한다.

## 사원 인증과 계정 화면

- 로그인 ID는 이메일이며 아이디 찾기 기능과 API를 제공하지 않는다.
- 회원가입 시 사번을 입력받지 않는다. 관리자가 가입을 승인할 때 시스템이 중복되지 않는 사번을 생성한다.
- 로그인 전 회원가입 화면에서 사용할 `GET /api/v1/signup-departments`를 제공하며 부서 ID와 이름만 반환한다.
- 비밀번호 재설정 메일 요청은 이메일 등록 여부와 관계없이 동일한 응답을 반환한다.
- 내 정보는 조회 전용이며 `GET /api/v1/me`로 현재 사용자 정보를 반환한다.
- 본인 정보 수정, 직접 비밀번호 변경과 사원 검색 기능·API는 제공하지 않는다.

## 멀티턴 질문

- 질문은 대화 단위로 이전 질문·답변 맥락을 이어간다.
- 첫 질문은 `conversationId` 없이 전송하고 백엔드가 새 ID를 생성해 응답한다.
- 후속 질문은 같은 `conversationId`를 전송하며 백엔드는 해당 사용자와 대화 ID가 일치하는 과거 질문·답변만 AI 문맥에 포함한다.
- 새 대화는 `conversationId`를 생략해 시작한다.
- 질문 이력은 `conversationId`로 필터링할 수 있다.
- 프론트엔드는 질문 유형을 보내지 않고 AI가 Wiki·일정·혼합 유형을 자동 판단한다.

## 문의 담당자

- 문의 등록자는 `APPROVED`·`ACTIVE` 상태의 모든 `ADMIN` 중 담당자 1명을 선택한다.
- 부서의 `manager_id` 지정 여부는 문의 담당자 후보 조건에 사용하지 않는다.
- 후보 목록에는 담당자 회원 ID, 관리자 이름과 관리자의 소속 부서 ID·이름만 표시한다.
- 사원도 후보를 조회할 수 있도록 `GET /api/v1/inquiry-assignees`를 제공하고 관리자 이름과 소속 부서를 반환한다.
- 문의 등록 시 백엔드는 선택한 회원의 가입 상태·계정 상태·역할을 다시 검증한다.
- 등록 후 담당자는 변경하지 않으며 지정 담당자만 문의를 조회하고 답변한다.
- `inquiry.assignee_id` 구조는 그대로 유지하므로 테이블 추가는 없다.

## 일정 파일

- 일정에는 별도 첨부파일이 없다.
- 일정 문서 업로드는 `TXT`, `MD`, `DOCX`, `PDF`, `CSV`, `XLSX` 원본문서 1개만 허용한다.
- 파싱 결과는 Markdown 파일 1개로 저장한다.
- 한 원본문서에서 추출된 여러 `schedule` 행은 같은 `source_group_key`, `source_original_path`, `source_parsed_path`를 참조한다.
- 수동 일정은 세 원본 관련 컬럼을 `NULL`로 저장한다.
- 같은 원본문서에서 추출된 마지막 일정이 삭제되면 원본문서와 파싱 파일도 삭제한다.
- `schedule.attachment_refs`, 일정 등록·수정의 `attachments`, 일정 첨부파일 다운로드 정책과 `/data/ajt/schedules/{scheduleId}/attachments` 경로를 제거한다.
- 관리자 일정 상세의 출처 문서 미리보기를 위해 기존 일정 첨부파일 다운로드 API를 `GET /api/v1/schedules/{scheduleId}/source-file`로 대체한다. 이 API와 원본문서 정보는 관리자에게만 제공한다.
- 일정 원본문서와 파싱 파일은 `/data/ajt/schedule-sources/{sourceGroupKey}/original`과 `parsed`에만 저장한다.

## 산출물 영향

- 요구사항 정의서: 사원 인증·계정 조회·멀티턴·문의 후보·일정 파일 요구사항을 수정한다.
- Postman: 가입용 부서 목록, 내 정보, 문의 담당자 후보 API를 추가하고 질문 요청·응답을 멀티턴으로 변경한다. 일정 첨부파일 필드·설명을 제거하고 원본문서 조회 API로 대체한다.
- SQL·ERD·PNG 와이어프레임: 이번 작업에서 수정하지 않는다.

## 검증 기준

- 요구사항 정의서와 Postman에 일정 첨부파일 정책이 남지 않아야 한다.
- 문의 담당자 후보 조건에 `department.manager_id`가 사용되지 않아야 한다.
- 문의의 이미지 첨부파일 정책은 그대로 유지해야 한다.
- 아이디 찾기·사원 검색·본인 수정·직접 비밀번호 변경 API가 없어야 한다.
- 질문 API가 `conversationId`를 요청·응답에 지원해야 한다.
- 생성된 Postman 컬렉션이 Collection v2.1 스키마를 통과해야 한다.
