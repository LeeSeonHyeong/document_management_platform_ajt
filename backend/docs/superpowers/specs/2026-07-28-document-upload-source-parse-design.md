# Wiki 원본문서 업로드·파싱 저장 설계

## 목표

관리자가 Wiki 원본문서를 여러 개 업로드하면 Spring Boot가 파일과 메타데이터를 저장하고, 문서를 하나씩 FastAPI에 전달해 파싱 Markdown을 저장한다. FastAPI는 DB나 서비스 파일에 직접 접근하지 않는다.

## 범위

- 공개 API `POST /api/v1/documents`를 Postman v1.0.0 계약 그대로 구현한다.
- Wiki 원본문서(TXT, MD, PDF, DOCX)만 처리한다.
- 원본 파일 저장, `wiki_scope`·`document`·`ai_job` 생성, 비동기 파싱 호출과 파싱 파일 저장을 포함한다.
- Wiki 변환·관계 반영·`index.md` 갱신은 포함하지 않는다.

## 요청과 업로드 검증

`files`, `documentCategoryId`, `visibilityType`, `departmentIds`를 multipart로 받는다.

- 파일은 1개 이상 20개 이하이며, 파일 하나는 20MB 이하이고 요청 전체는 100MB 이하다.
- 허용 MIME/확장자는 TXT, MD, PDF, DOCX다.
- `visibilityType=all`이면 `scopeKey`는 `ALL`이다.
- `visibilityType=department`이면 부서 ID를 중복 제거·오름차순 정렬해 `D1-D2` 형식의 `scopeKey`를 만든다.
- 지정한 문서 카테고리는 계산한 `scopeKey`에 속해야 한다.
- API 계약에 임시 업로더 헤더나 파라미터를 추가하지 않는다.

## 인증 경계

컨트롤러와 서비스는 `CurrentMemberProvider`를 통해 현재 로그인한 관리자의 ID와 역할을 얻는다. 인증·회원 모듈이 합쳐질 때 이 포트의 구현체만 실제 보안 컨텍스트 기반으로 교체한다. 인증되지 않았거나 관리자가 아니면 표준 401 또는 403 오류를 반환한다.

## 저장 모델과 파일 경로

로컬 파일 저장 루트는 설정값으로 분리한다. 원본 파일과 파싱 Markdown은 `scopeKey`와 문서 ID별 경로에 보관하며, 외부 응답에는 실제 경로를 노출하지 않는다.

업로드 요청은 다음을 생성한다.

1. 아직 없는 `wiki_scope`는 공개 범위에 맞춰 생성한다.
2. 각 원본 파일에 대해 `document` 행을 `UPLOADED` 상태로 생성한다.
3. 한 요청의 문서 ID 배열을 가진 `ai_job` 한 건을 `WAITING` 상태로 생성한다.
4. 원본 파일은 DB 행과 연결할 수 있는 경로로 저장한다.

DB 저장이 실패하면 해당 요청에서 새로 저장한 원본 파일을 삭제한다. 파일 저장이 실패하면 관련 DB 행을 커밋하지 않는다.

## 비동기 파싱

`ai_job`은 단일 스레드 실행기로 처리한다. 따라서 업로드 요청은 여러 개여도 Wiki 문서 작업은 전역적으로 동시에 실행되지 않는다.

한 업로드 요청의 파일은 묶음으로 저장하지만 FastAPI에는 하나씩, 업로드 순서대로 보낸다.

1. 작업 시작 시 `ai_job`을 `PROCESSING`으로 바꾼다.
2. 다음 문서를 `PARSING`으로 바꾼다.
3. 원본 파일과 검증된 메타데이터를 `POST /internal/v1/source-parses`에 보낸다.
4. 성공 응답의 `parsedMarkdown`을 파일로 저장하고 `document.parsed_path`를 갱신한다.
5. 파싱에 성공한 문서는 아직 Wiki 변환이 끝나지 않았으므로 `PROCESSING` 상태로 둔다.
6. 파싱 실패 문서는 `FAILED` 및 사람이 확인 가능한 실패 사유를 저장한다. 다음 문서는 계속 처리한다.

Wiki 변환이 아직 구현되지 않았으므로 파싱 단계만으로 문서 또는 작업을 `COMPLETED`로 바꾸지 않는다. 파싱이 끝난 작업은 후속 Wiki 변환 단계가 시작될 때까지 `PROCESSING` 상태로 유지한다.

파싱 결과 파일 저장에 실패하면 결과 파일을 삭제하고 해당 문서를 `FAILED`로 기록한다. 원본 파일은 유지한다.

## 오류 처리

- 업로드 검증 실패: `INVALID_DOCUMENT_UPLOAD`, 400
- 현재 사용자 없음: 401
- 관리자 아님: 403
- 카테고리·부서 범위 불일치: 400
- FastAPI의 오류 또는 응답 계약 위반: 해당 문서에 실패 사유를 남긴다.
- 원본·파싱 파일 I/O 실패: 해당 문서 또는 요청의 영속 상태와 파일이 불일치하지 않도록 정리한다.

## 테스트 기준

- 업로드 계약과 각 파일·총량·공개 범위 검증
- 부서 ID 정렬·중복 제거에 따른 `scopeKey` 생성
- `wiki_scope`, 문서, 작업 생성과 202 응답
- 문서별 순차 FastAPI 호출 및 성공한 파싱 파일 저장
- FastAPI 실패 후 다음 문서를 계속 처리하는 동작
- 파싱 파일 저장 실패 시 실패 상태와 생성 파일 정리
- 관리자·비관리자·미인증 접근 제어

## 제외 사항

- 일정 원본문서 업로드·파싱
- Wiki 변경안 생성·적용, 관계 JSON 갱신, `index.md` 갱신
- 원본문서 목록·상세·수정·삭제 API
- 실제 JWT/세션 인증 구현
