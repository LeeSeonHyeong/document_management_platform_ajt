# 2026-07-29 챗봇 1·2단계 — haiku 단독

## 무엇을 재려 했나

두 엔드포인트(`answer-context-selections`·`answers`)를 처음 실기동하고, 1단계에 작은
모델(`claude-haiku-4-5-20251001`)로 충분한지 본다. 위키는 `2026-07-27-opus46-12docs` 가
만든 20페이지를 그대로 쓰고, 정답 위키 ID 는 목차를 보고 사람이 정했다
(`chat_questions.json`). 일정 5건은 실물이 없어 만들었고, 위키와 주제가 겹치는 것을 일부러
섞어 `mixed` 분류가 시험되게 했다.

`bfd285bfd962`(스톡옵션)와 `2d0c4dd38694`(오프보딩)를 **둘 다** 골랐다 — 5개 상한에서
하나만 고르고 멈추지 않았다.

`mixed` 질문("오프사이트 예산이 얼마고 올해 언제야?")은 위키 `6466ec527a71` 와 일정
`9002` 를 함께 골라 `mixed` 로 분류했다.

## 2단계 — 2질문

둘 다 200, 답변이 자료 안에 머물렀고 출처가 정확히 하나씩 붙었다.

```

  → "무제한 휴가 정책… 연간 최소 25일(공휴일 포함)은 반드시 사용"

  → sources: [wiki b63430958f86 도서 지원 정책]
```

`quality` tier(`claude-sonnet-4-6`)는 쓰지 않았다. haiku 로 이 품질이 나왔으므로 대조의
근거가 아직 없다.

## 판정

**haiku 로 충분하다.** 1단계는 8/8 이 1순위이고 분류도 8/8 이다. 2단계도 근거 안에 머물고
출처가 맞다. `quality` tier 를 sonnet 으로 둔 기본값은 유지하되, 비용이 문제가 되면 2단계도
haiku 로 내릴 근거가 이 측정에 있다.

**오답 유입은 문제로 보지 않는다.** 평균 1.4개가 섞이지만 전부 인접 주제이고(연차 질문에
육아휴직·복지 개요), 계약이 "관련도 순서로 최대 5개"라 상위가 맞으면 Spring 이 그것부터
읽는다. 2단계 답변도 실제로 쓴 것만 출처로 냈다.

## 미해결

**정답 라벨이 너무 엄격한 곳이 있다.** 2단계 실행에서 "연차 며칠까지 쓸 수 있어?"가
일정 `9001`(8월 여름 휴가 기간)을 함께 골라 `mixed` 로 분류했다 — 1단계 단독 실행에서는
`wiki` 였다. 같은 질문이 실행마다 갈리며, **`mixed` 쪽이 더 나은 답일 수도 있다**(연차를
묻는 사람에게 권장 휴가 기간은 유용하다). 라벨을 고치기 전에 사람 판단이 필요하다.

**`quality` tier 미측정.** sonnet-4-6 로 2단계를 돌린 수치가 없다.

**목차 확장성 미측정.** 20페이지 목차가 3,955 토큰이다. 200페이지면 선형으로 늘어나고
1단계 비용이 그만큼 오른다. 이 실험으로는 드러나지 않는다.

## 비용과 게이트웨이

호출 16건, input 68,651 토큰, output 2,661 토큰. haiku input 100토큰 ≈ 1크레딧 환산으로
**약 690크레딧**이다.

| 경로 | 건수 | 평균 input |
| --- | --- | --- |
| `answer-context-selections` | 14 | 3,953 |
| `answers` | 2 | 6,649 |

계획은 205크레딧을 예상했다. 초과 원인 둘.

1. **게이트웨이가 프롬프트 캐싱을 지원하지 않는다.** 원시 curl 로 `cache_control` 을
   정확히 붙여 같은 목차를 두 번 보내도 `cache_creation_input_tokens` 와
   `cache_read_input_tokens` 가 모두 0 이다. 우리 클라이언트가 그것을 전송한다는 것은
   mock 서버로 확인했으므로(`tests/api/test_prompt_cache.py`) 원인은 게이트웨이다.
   1단계 8질문이 150 대신 약 320크레딧이 됐다.
2. **단계적 확인으로 1단계를 14번 불렀다** (스모크 1 + 3 + 8 + 2단계 재실행 2). 8번이
   아니다. 이건 의도한 안전 비용이다 — 8질문을 한 번에 돌리기 전에 배관을 확인했다.

캐싱 전제는 폐기한다. spec 의 예산 절과 `answer_context_instruction` 의 주석을 고쳐야
한다. **`cache_control` 을 붙이는 코드는 남긴다** — Anthropic 직결로 바꾸면 그때 살아나고,
붙여 둔 것이 손해는 아니다.
