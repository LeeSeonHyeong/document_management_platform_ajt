신입 구성원이 회사에 빠르게 적응하도록 돕는 온보딩 체계를 정리한다. 입사 후 4주간 진행되는 일정과 완료해야 할 체크리스트, 온보딩 담당자 제도, 첫 주 과제, 수습기간 체크인까지 다룬다.

## 입사 후 4주 일정

입사 첫날부터 4주차까지 주요 일정은 다음과 같다[^20].

| 시기 | 내용 |
| --- | --- |
| 입사 1일차 | 인사팀 오리엔테이션, 사내 시스템 계정 발급, 보안 서약서 작성 |
| 1주차 | 소속 팀 배치, 팀장 면담, 사내 도구 교육 |
| 2주차 | 담당 업무 인수인계, 사내 규정 숙지 |
| 4주차 | 수습 중간 점검 면담 |

## 온보딩 체크리스트

입사 후 완료해야 할 기본 항목은 다음과 같다[^21].

| 항목 |
| --- |
| 인사시스템 계정 등록 |
| 사내 메일·메신저 계정 발급 |
| 보안 서약서 제출 |
| 팀장 면담 완료 |

인사팀은 신입사원마다 온보딩 체크리스트를 사내 이슈 관리 도구에 등록해 관리한다[^1]. 입사 전에는 환영 이메일을 통해 첫 출근에 필요한 절차를 안내한다[^2].

> 입사 후에는 이메일로 중요한 업무 지시를 하지 않는다. 이메일만으로 오는 지시는 의심해야 한다[^3].

## 온보딩 담당자 제도

모든 신입사원에게 온보딩 담당자가 배정되며, 대개 합류할 팀의 팀장이나 선임 구성원이 맡는다[^4]. 온보딩 담당자 운영 원칙은 다음과 같다[^5].

| 시점 | 온보딩 담당자가 하는 일 |
| --- | --- |
| 배정 직후 | 신입사원과 먼저 인사를 나누고 일정 조율 |
| 첫 3일 | 첫 주 안내 목록과 직무별 과제를 함께 진행 |
| 이후 몇 주 | 최소 주 1회 안부 확인 |

온보딩을 처음 맡는 담당자는 인사팀이나 팀장에게 경험자와 짝을 이뤄 달라고 요청할 수 있다[^6].

## 첫 주

```mermaid
graph LR
    A[팀장과 30·60·90일 목표 논의] --> B[장비·계정 지급]
    B --> C[구성원 소개 미팅]
    C --> D[실사용자와 대화]
    D --> E[작은 개선·버그 수정 진행]
```

신입사원은 첫 주에 팀장과 만나 이후 30일·60일·90일의 목표를 논의하고[^7], 필요한 장비와 계정 접근 권한을 지급받는다[^8]. 작은 개선이나 버그 수정을 직접 진행해보며 업무에 빠르게 적응한다[^9].

### 엔지니어 온보딩

엔지니어 온보딩에서는 다섯 가지 원칙을 따른다[^10].

1. 첫날 작은 작업이라도 함께 배포까지 완료한다.
2. 매일 온보딩 담당자와 학습 세션을 진행하여 필요한 맥락을 전달한다.
3. 팀에 중요한 주제로 브레인스토밍을 최소 한 번 진행하고 결론을 문서로 남긴다.
4. 가능한 한 페어 프로그래밍으로 함께 작업한다.
5. 업무 외 시간도 함께 보내며 친밀감을 쌓는다.

## 우리가 사용하는 도구

전사적으로 사용하는 도구는 다음과 같다[^11].

| 구분 | 도구 |
| --- | --- |
| 협업 및 커뮤니케이션 | 사내 메신저, 그룹웨어 |
| 개발 | GitHub, AWS |
| 디자인 | Figma |
| 영업·고객지원 | Salesforce, 고객지원 플랫폼 |

## 수습기간과 30·60·90일 체크인

팀장은 신입사원의 수습기간(입사 후 3개월) 동안 정기적으로 피드백을 제공할 책임이 있다[^12]. 30일·60일 체크인에 이어 80일 체크인에서 수습 종료 전 마지막 피드백을 전달하며[^17], 90일에 수습기간이 끝난다[^13].

팀장은 수습 통과에 우려가 있다면 체크인을 기다리지 말고 즉시 인사팀에 알려 대응 시간을 확보해야 한다[^14]. 수습기간을 통과한 이후의 성장 경로와 평가 체계는 [경력 개발 및 승진 체계](pages/a7a15a57c025.md)에서 다룬다.

## 궁금한 점 찾기

궁금한 내용이 있으면 먼저 사내 위키와 문서를 검색해 스스로 답을 찾아본다[^15].

## 사내 소통 채널

업무 관련 채널 예시는 다음과 같다[^18].

| 채널 | 용도 |
| --- | --- |
| 공지 | 전사 공지사항 |
| 개발 | 개발 관련 논의 |
| 전사 | 자유로운 전체 대화 |

이 외에도 취미·관심사를 주제로 한 사내 소모임 채널을 자유롭게 만들 수 있다[^16]. 다만 성별·정치 성향·종교·연령 등 채용 과정에서 차별 사유가 될 수 있는 주제의 채널은 만들지 않는다[^19].
