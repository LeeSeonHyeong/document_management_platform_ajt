# AI 담당 범위 설계 — `ai/` 외부 수정 금지와 확인 게이트

- 작성일: 2026-07-28
- 대상: `ai/CLAUDE.md`
- 범위: 에이전트가 이 저장소에서 어디를 고칠 수 있는지. 코드 동작 변경 없음
- 근거: 루트 `CLAUDE.md`(저장소 구성·docs 단일 관리) · `../docs/api/README.md`(계약 변경 절차)

## 1. 배경

저장소 하나에 `backend/`·`frontend/`·`ai/`·`docs/`가 함께 있고 담당자가 나뉘어 있다.
AI 담당자는 `ai/` 만 고친다. 그런데 그 사실이 어디에도 적혀 있지 않았다.

에이전트에게 이 경계가 없으면 두 방향으로 새어 나간다. 계약과 백엔드 응답이 어긋날 때
`backend/` 를 직접 고치거나, 반대로 `ai/` 안에 우회 구현을 넣어 불일치를 덮는다. 둘 다
담당자가 모르는 변경을 만든다.

## 2. 결정

### 2.1 자리는 `ai/CLAUDE.md`

이 규칙의 독자는 사람이 아니라 에이전트다. 따라서 `ai/` 작업 시 자동으로 컨텍스트에
들어오는 곳에 있어야 한다.

| 후보 | 자동 로드 | 판정 |
| --- | --- | --- |
| `ai/CLAUDE.md` | `ai/` 작업 시 들어온다 | **채택** |
| `ai/README.md` | 수동 | 서버 설명 문서. 작업 규칙과 독자가 다르다 |
| `ai/docs/superpowers/` | 수동 | 설계 이력 자리. 항상 유효한 규칙에는 안 맞는다 |

`ai/README.md` 는 스택·모듈 설계를 이미 충실히 담고 있어서, `CLAUDE.md` 에 그 내용을
복사하지 않는다 (루트 `CLAUDE.md`: 문서 내용은 다른 곳에 복사하지 않는다).

### 2.2 읽기 자유, 수정 금지

`backend/`·`frontend/`·`docs/`·루트 파일은 동작 확인을 위해 읽는 것은 자유지만
수정·생성하지 않는다. 변경이 필요하면 담당자와 소통해 그쪽에서 처리한다.

- 백엔드 요청·응답이 계약과 다르면 → 백엔드 담당자에게 알린다
- 계약(`../docs/api/`) 자체를 바꿔야 하면 → `../docs/api/README.md` 절차를 따른다
- ERD·요구사항 수정이 필요하면 → 해당 담당자에게 알린다
- 계약 불일치를 `ai/` 안의 우회 구현으로 덮지 않는다. 기록하고 알린다

### 2.3 명시적 지시에도 확인 게이트

"절대 금지"만 적으면 사용자의 직접 지시와 충돌한다. 사용자 지시가 `CLAUDE.md` 보다
우선하므로 실제로는 고치게 되고, 그러면 문서가 지켜지지 않는 문장을 담게 된다.

그래서 금지를 확인 절차로 바꿨다.

1. `ai/` 밖 수정 지시를 받아도 바로 고치지 않는다
2. 어떤 파일을 왜 어떻게 바꿀지 먼저 제시한다
3. 확인은 그때 제시한 그 파일·그 변경에만 유효하다. 다음 파일이나 다음 턴으로 넘어가지 않는다

승인이 확장되지 않는다는 3번이 핵심이다. 한 번의 "고쳐줘"가 세션 내내 유효한 통행증이
되면 경계가 사라진다.

### 2.4 git stage 범위

경계가 수정 단계에서만 지켜지면 부족하다. 루트가 단일 저장소라 `git add -A` 한 번으로
담당자 파일이 함께 스테이징된다.

- stage 는 `ai/` 하위 경로만 명시한다. `git add -A`, `git add .` 를 쓰지 않는다
- 커밋 전 `git status` 로 `ai/` 밖 변경이 섞이지 않았는지 확인한다

## 3. 함께 처리한 문서 공백

담당 범위를 정하면서 `ai/` 문서와 실물을 대조했다. 실제 공백 3건.

| 건 | 조치 |
| --- | --- |
| `.gitignore` 에 `.env` 없음 — `CLAUDE.md` 는 "`.env*` 커밋 금지"라고 지시하는데 무시 규칙이 없어 실수로 커밋 가능 | `.env` 한 줄 추가 |
| `.env.example` 없음. 기동에 필요한 변수를 알 방법이 없음 | `src/.env.example` 신규 (`INTERNAL_API_KEY`·`WORKSPACE_PATH`·`APP_URL`). 위치가 `src/` 인 이유는 `wiki_mcp/config.py` 가 `Path(__file__).parent.parent / ".env"` 를 읽기 때문 |
| `CLAUDE.md` 패키지 표가 패키지 단위라 각 패키지에서 무엇부터 읽을지 알 수 없음 | 진입 파일 표 추가. 각 파일 docstring 이 정본이라는 점 명시 |

## 4. 오판 1건과 그 교훈

검토 중 `viewer/`·`experiments/INDEX.md`·`report.json`·`graph.json`·`wiki_mcp.graph_api`
가 트리에 없다고 보고했다. `CLAUDE.md` 가 없는 것을 정본이라 지칭한다고 판단했다.

**틀렸다.** 전부 `origin/develop` 에 있다. 작업 브랜치
`feature/S15P11B106-118-source-parse-api` 가 develop 보다 뒤처져서 안 보였을 뿐이다.

이 오판이 실제 손상을 낼 뻔했다. 없다고 판단한 산출물을 근거로
`.gitignore` 에 `experiments/*/data/work/` 를 넣었고, 그 규칙은 develop 이 추적하는
`experiments/2026-07-27-reingest/data/work/9001/state.json` 을 무시한다. `git check-ignore`
로 잡아 되돌렸다.

교훈: **파일 부재를 문서 오류로 판단하기 전에 다른 브랜치를 확인한다.** 이 저장소에서
`ai/` 작업 브랜치는 develop 보다 뒤처져 있는 것이 정상이므로, 작업 트리의 부재는
드리프트의 근거가 되지 않는다. 확인 명령:

```bash
git ls-tree -r --name-only origin/develop -- ai/<경로>
git branch -a --contains <커밋>
```
